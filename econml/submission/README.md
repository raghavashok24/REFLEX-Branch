## Why the zip is built from git

`build_package.py` reads every member from `git show HEAD:...`, never from the
working tree, and refuses to write the zip if any member matches an identifying
pattern. This is deliberate: `__pycache__/*.pyc` and `paper/main.log` are
untracked build leftovers that embed an absolute path with a machine username,
so a zip of the working directory would break the blind. Exporting from git
cannot pick them up.

## Pre-submission checks

All of these pass as of the v6 build:

- **Page budget.** Body ends on page 9; References open page 10. Appendices and
  references are unlimited at this venue and do not count.
- **Certificates.** 542 assertions across eight files, all passing, matching the
  per-file counts in Appendix H.
- **Blind.** No author block, empty PDF metadata, no URLs, self-citations in the
  third person, and no identifying string anywhere in the zip.
- **Build integrity.** No undefined references or citations; `main.pdf` rebuilt
  from the current sources.
- **Abstract.** 247 words, under the 250-word limit.

## What is not in this submission, and is not editorial

The measured-alignment panel, which would put `lambda_max` on real deployed
models, is not built. Both recorded external reviews named it as the item that
moves this from poster to oral. It is gated on a data check nobody has run, and
its protocol is written up in [`../paper-updates/`](../paper-updates/) for the
camera-ready. Section 8, the Table 1 status column and the limitations section
all say so in the paper itself.
